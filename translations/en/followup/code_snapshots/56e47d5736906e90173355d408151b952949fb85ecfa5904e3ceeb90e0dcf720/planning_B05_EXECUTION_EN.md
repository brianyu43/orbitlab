# B05: Execution details connecting from image expression to actual intervention

2026-09-23. This is the execution plan after the B04 fixed evaluation. The status reader completed 6 rounds of learning and revision evaluation, and verified the entire RGB intervention connections and playback for 640 new scenes and 2,961 tasks. [Final fixed evaluation](../../reports/object_image_edit_v1/RESULTS_EN.md) and [Reading evaluation revision](../../reports/object_readout_pose_corrected_v1/RESULTS_EN.md) are referenced. Below are the steps and boundaries used for actual execution. The completion of the B05 evaluation does not mean achieving successful editing capabilities.

## The boundary between questions and comparison

We investigate whether the expression obtained from RGB contains information about shape, color, position, size, and direction, and whether we can only change the requested target using that information. Simply applying video transformation to a mask makes it easy to extract an unknown rotation center or obscured area from the answer. Therefore, we separate the stage of reading the state from the stage of executing commands in the expression.

The existing flat/Slot Attention encoder/decoder is fixed. The learning of the head that reads object states uses the train's ground‑truth properties as supervision signals. **It does not call it an experiment that discovers concepts without ground‑truth.** It does not insert ground‑truth states or masks into image inputs. The intervention controller distinguishes the learning model of B03 from explicit ground‑truth rules, connects them, and the former measures how much it can tolerate perceptual errors based on the rules learned from already known states.

## Small execution units

1. **RGB representation cache:** In each split, only RGB is read and stored in the fixed encoder's 5×32 slots. The train and evaluation random flow are fixed, and checkpoint, RGB, and latent hashes are recorded. The ground truth property file can only be accessed via a separate loader.
2. **State Reading head:** Predicts the 16 state components for each slot using shared MLP. Supervises by assigning the minimum cost between the two actual objects in the training and the five-digit predictions. Separates the losses for categories/coordinates/sizes/directions/presence, and checks whether the loss remains the same even if the GT object order is swapped. Scores both empty slots and overlapping detections together.
3. **Independent perception evaluation:** Does not provide the number of correct answers or corresponding responses to the model. The evaluation measures the missing/duplicate/shape/color/coordinate/direction by matching predictions and correct answers. It evaluates the same volume for three or four objects and obscures, distinguishing between the separation of visible areas and the inference of obscured properties.
4. **Target Specification:** Do not provide a persistent object ID that is not visible in the image model as input. Specify the target using a point marker that the actual user can provide. Fix the generation rules for the selected location and the amount of additional information, and measure target selection errors and transformation errors separately. Do not inadvertently pass the center and rotation axis from the correct answer.
5. **Intervention connection:** Each of the shared-object controller and analytic rule inputs the B03 that has the prediction state fixed. Both the color·90° rotation·movement·color after rotation synthesis are evaluated. The synthesis does not include the intermediate answer. The identity baseline is also included.
6. **Response maintenance and success criteria:** Maintain the response determined in the initial state evaluation even after intervention, and re-respond to the prediction that changes to another object, not counting it as a success. Report changes to the target, the remaining properties of the target, non-target states, existence/number, and the overall scene success and continuous error.
7. **Error Transmission Analysis:** Divide the correct state → controller, predictive state → analytic rule, predictive state → controller and compare bottlenecks of lag, selection, and rule execution. Multiple commands in the same scene are grouped by scene unit to calculate uncertainty.

## Verification experiment operation

Head development is limited to train/validation. The test observed in the B04 analysis is not referred to as a completely independent verification dataset for a new learning method. After locking in the final head configuration, the existing results are separated to create a verification dataset for a new data seed, and the original rotation trajectories are checked for overlap. The results of the original 6,356 intervention tasks can be reported as a separate fixed model transfer diagnostic.

Even if a step fails, it leaves a result and does not reduce the subsequent comparison requirements. If the state reading is not accurate, report this fact as a delay bottleneck and continue the independent work with external SVIB and kinematics. The completion of B05 is judged when it is connected from image input to actual intervention output, target selection, non‑target preservation, object count/combination evaluation, and then verified by playback.
