# OrbitLab 생성 성공률 회복: 새 자료 확인 결과

**결론:** 잠재 공간 flow의 학습을 4,000→16,000단계로 늘리면 자동 엄격 통과율이 세 새 데이터 seed의 모든 초기화에서 개선됐다. 그러나 성공한 그림만 모았을 때 작은 크기의 도형이 부족하고 특정 조건의 성공 표본이 적어, 미리 정한 **최종 이정표는 통과하지 못했다.** 작업은 실험·검증까지 완료됐으며 제품 수준의 생성기 완성으로 해석해서는 안 된다.

## 무엇을 어떻게 비교했나

개발 단계에서 F0 조건부 C4 잠재 flow의 4천 단계와 1만6천 단계만 최종 비교 대상으로 골랐다. 두 설정은 **같은 AE, 같은 logit mean 디코더, 같은 flow 초기화·자료·optimizer의 4천 단계 체크포인트**를 공유한다. 후보는 여기서 1만2천 단계 더 학습한다. 생성 시 둘 다 Euler 64단계, guidance 1.0, 동일한 조건·noise를 사용한다. 차이는 flow 학습량이다. 모델과 평가 기준은 [사전 고정 파일](lock.json)에 남겼다.

확인 자료는 seed 770201·770202·770203의 독립 합성 장면이며, seed마다 초기화 3개를 새로 학습했다. 각 모델은 본 조합 20×128=2,560개와 학습에서 제외한 조합 4×128=512개, 총 3,072개를 생성했다. 두 학습 길이의 경로는 모두 18개다. [자료 명세](data/manifest.json)에는 이전 자료와 중복되지 않은 기본 장면의 회전 궤도 33,024개가 기록돼 있다. 다만 세 seed는 동일한 합성 생성기에서 나온 것이므로 현실 세계 일반화의 독립 검증은 아니다.

표는 seed별로 세 초기화를 평균한 뒤 세 seed를 동등하게 평균한 것이다. 생성 이미지 수를 독립 실험 횟수처럼 세지 않았다. 원자료·조건별 행·개별 결과와 계산식은 [확인 결과](evaluation/summary.json)에 있다. 확인용 깨끗한 test/OOD 그림의 AE→디코더 재구성은 평균 엄격 통과 86.28%/86.46%였으므로, 그보다 낮은 생성 결과에는 flow가 실제 인코딩 코드의 분포를 충분히 만들지 못하는 문제도 남아 있다. 이는 진단적 비교이며 원인을 하나로 증명하지 않는다.

[세 seed의 대응 결과와 크기 다양성 그림](figures/confirmation_overview.png)을 보면 성공률은 모두 상승했지만, 성공 그림의 크기 분포 막대는 세 seed 모두 점선 기준을 넘는다. 공유·인쇄용 벡터 파일은 [PDF](figures/confirmation_overview.pdf)로 저장했다.

## 왜 최종 이정표가 실패했나

후보의 **모든 생성물**은 세 seed에서 중심·크기·방향 다양성 기준을 모두 통과했다. 그중 **엄격하게 성공한 그림만** 모으면 크기 분포의 총변동거리(TV)가 seed별 0.283, 0.274, 0.256으로, 사전 상한 0.20을 넘는다. 모양 2·색 0에서는 seed마다 세 초기화의 384개 생성 중 엄격 성공이 각각 11, 7, 15개로, 조건별 다양성을 판정할 최소 32개에도 못 미친다. 성공 그림이 특정 크기에 몰렸다는 뜻이다. 원래 데이터 생성기의 크기 분포를 모두 따라가면서 성공하는 수준은 아직 아니다.

모양 2의 생성 그림을 판독기가 작게 추정한 구간에서 엄격 성공은 2.45%, 크게 추정한 구간에서는 15.18%였다. 이 구간은 **생성물에서 추정한 크기**라서 잘못 그린 그림의 실제 크기를 보증하지 않는다. 다만 작은 윤곽의 형상·선명도가 특히 취약하다는 후속 가설을 뒷받침한다. 붉은색 모양 2는 9경로 전체의 엄격 통과가 약 2.9%에 그친다. 색 자체의 일치는 높으므로 결손은 주로 모양과 엄격 윤곽 기준에서 발생한다. ## 시간·검증·한계

CPU 4스레드에서 9경로의 총 학습 시간은 AE 약 72분, 디코더 약 25분, 4천 단계 flow 약 1분, 추가 1만2천 단계 flow 약 3분이었다. 한 경로에서 학습 연장은 평균 약 20초였고, 생성 비용은 두 설정 모두 샘플당 raw C4 velocity 평가 256회로 동일했다. 이 결과는 이 작은 합성 모델에서 **flow를 더 학습하는 것이 비용 대비 큰 개선을 준다**는 실험 근거다. 다른 문제로 일반화한다는 뜻은 아니다.

[재계산 검증](evaluation/verification.json)은 18개 결과의 checkpoint·source·noise 해시, 첫 8개 생성 latent 재생, 행별 지표와 다양성 집계를 확인했다. [학습 전 점검](pre_evaluation_training_audit.json)에서는 9개 AE/디코더와 4천·1만6천 단계 checkpoint를 확인했다. 원본 실행 래퍼에는 추가 학습 단계의 출처 필드가 하나 빠져 첫 경로에서 `KeyError`가 났다. 모델 상태나 평가 코드를 바꾸지 않고 해당 필드만 보완한 [실행 수정 기록](execution_amendment_01.json)을 확인 평가 전 별도 고정했다. 기존 체크포인트에서 재개했으며 test/OOD 점수를 보고 고친 것은 아니다.

다음 연구는 이 확인 결과로 같은 후보를 다시 고르는 것이 아니라 별도 개발·확인 seed를 정한 새 프로토콜로 해야 한다. 먼저 모양 2와 작은 크기의 실패를 그림·latent·윤곽 측정으로 나누고, 크기별 균형 표본 추출 또는 공간 구조를 가진 표현 중 한 변경만 시험하는 편이 합리적이다. 고정 평가 기준은 그대로 두고, 성공 표본의 다양성까지 목표에 넣어야 한다. 사람 판독 결과와 다른 도형·현실 영상에서의 성능은 아직 없다.
