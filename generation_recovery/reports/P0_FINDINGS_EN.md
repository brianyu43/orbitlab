# P0 Diagnostic Findings: Single-Shape Generation

2026-09-23. This document does not report the performance of a new model. We first narrowed down possible causes using existing saved models and small training sets.

The rotational orbits of 1,792 new development base images did not overlap the 11,776 previously recorded orbits. Shape/color label order, pixel range, and train/validation/test/excluded-combination splits were correct. When 96 saved generated representations were rendered again on CPU, all 96 shape, color, and strict judgments matched the saved judgments. Rotation-related encoder, decoder, and flow errors were each at most 1e-5. [Data and rotation checks](p0_data_c4_v1.json) · [saved-result replay](p0_saved_replay_v1.json)

All 768 clean images directly drawn using the known shape-generation rules passed both shape/color and strict evaluation. This weighs against the explanation that the 15.6% rate is low mainly because the evaluator rejects valid images. This is a non-learning reference that uses the known rules. [Clean-image evaluation](p0_clean_renderer_v1.json)

For 768 images generated from one existing C4 model with the same noise, Euler 64 achieved strict success of 18.28% on training combinations and 11.72% on excluded combinations. Heun 32, using the same 64 velocity evaluations, achieved 18.44%/10.16%; Euler 256 achieved 18.28%/10.16%. There is no evidence here that more accurate integration or more steps alone resolve the problem. This small sample from one development checkpoint does not replace the independent 15.6% confirmation result. [Solver comparison](p0_solver_v1.json)

After training an AE for 6,000 steps on 64 images covering all 20 training combinations, 98.44% of the four rotated reconstructions of those images passed strictly. A flow then trained for 4,000 steps on 20 encoded examples, one per combination, attained 88.13% shape accuracy and 65.00% strict success with eight new noise samples per training condition. The AE nearly memorized the small set, but the flow's fresh generations still varied in shape and outline within the same condition. This is a diagnostic on training conditions, not a generalization score for new images. [Small AE run](../runs/tiny_v1/ae/run.json) · [small flow run](../runs/tiny_v1/flow/run.json) · [generated examples](../runs/tiny_v1/flow/train_condition_samples.png)

Saved generated representations differed from encodings of actual training images in their distributions and reconstruction-cycle errors. These are descriptive statistics suggesting a mismatch in the intermediate representation, not proof that generated codes are outside the representation space. In particular, excluded combinations have no training codes under the same condition, so a same-condition nearest-neighbor distance cannot be defined. [Latent diagnostic](p0_latent_v1.json)

We validated the diversity reader on 2,048 rotated real images. Because a zigzag appears identical after a 180-degree rotation, it uses two distinguishable orientation bins. This measurement correction and the center/size bins were fixed before inspecting model results. [Reader definition](p0_diversity_reader_lock_v1.json) · [amendment rationale](../AMENDMENT_01_EN.md)

The first priority is the P1 comparison separating decoder effects on outlines from flow effects on conditioning. The new concat implementation exactly reproduces the old flow's initial weights and outputs. FiLM has 8.56% more parameters and passed rotation numerical checks and a training-signal check. A performance difference between these architectures should not be interpreted immediately as the pure effect of conditioning. [Model preflight](p1_model_preflight_v1.json)
