## 입력 정보를 비교할 때

| 실험 | 추론 입력과 명시적 도움 | 추가 학습 감독·주의점 |
|---|---|---|
| R1 | 알려진 물체 crop과 renderer를 통제한 이미지 | 모양·방향·색 등 상태 감독. template는 알려진 renderer 참조. 일반 객체 검출과 다르다. |
| R3 | 정답 초기 상태, 알려진 또는 4프레임에서 추정한 외력 | 상태 전이 감독. 영상 외력 참조는 팔레트·원형·적분 규칙을 안다. contact는 물리 접촉 사전 지식이 추가된다. |
| R2 | 검출/정적 슬롯은 현재 한 장, 순환 모델은 현재+과거 네 장 | 모두 정답 상태 감독, 일부 mask 감독. 검출기는 중심 heatmap도 받는다. 신경 편집기의 원본 RGB 접근과 상태 교체를 공개한다. |
| R4 | 실제 image encoder 또는 별도 정답 속성 입력 | coordinate에는 중심 감독, bridge에는 속성 감독이 추가된다. 다른 입력 역할마다 따로 학습한 decoder를 고정 decoder 교체처럼 해석하지 않는다. |
| R5 외부 primary | source RGB 한 장 | target RGB MSE만 사용. 정답 위치·마스크·속성은 primary 입력/손실에 들어가지 않는다. object와 plain/C4는 파라미터 수가 다르다. |
| R5 외부 측정기 | 생성/정답 RGB와 정답 source 중심의 고정 crop | 정답 속성 감독으로 별도 학습. 생성기의 추가 정보와 섞지 않는다. 조합별 정답 판독 성능을 공개한다. |
| R5 통합 원형 물체 | 네 RGB 프레임, 클릭·행동; 검은 배경/원형/동일 질량/반경 범위 사전 지식 | 인식/힘은 정답 상태·힘 감독, decoder는 영상 손실과 좌표 배치 구조. 정답 상태·힘·renderer는 명시적 교체군에만 준다. |

계산 예산은 각 보고서의 파라미터·본 학습 업데이트·별도 시간 측정 업데이트·실제 초를 함께 본다. 같은 업데이트 수라도 한 업데이트의 계산량이 같지는 않다. 동시 실행의 벽시계 시간 합을 전체 경과 시간으로 쓰지 않는다. [GPU 병렬 적용 근거](r5/GPU_SCHEDULING_AMENDMENT.md)

## 최종 묶음 전에 확인할 항목

1. 외부 모든 필수 셀과 개발 선택으로 요구되는 확인 셀이 완료되거나 자원 상한으로 미완료임이 명시되어야 한다. `r5_external_report.py --require-complete`는 미완료 셀이 있으면 실패한다.
2. 모든 seed·실패·입력 정보·실제 비용·코드/가중치/데이터 출처·재현 명령이 최종 묶음에 연결되어야 한다. 현재 보고서 생성기는 가중치를 새로 학습하지 않는다.
3. 마지막 원본 보존 감사를 다시 실행하고, 이전부터 존재하던 불일치와 이번 변경을 구별해야 한다. `scripts/verify_artifacts.py`처럼 역사적 파일을 수정하는 도구로 원본을 고치지 않는다.
4. 독립 사람 평가의 적용 여부를 실제 개선 결과로 판단하고 수행 여부를 명시해야 한다. 참여자가 없으면 미수행이며 AI 판독으로 대체 완료하지 않는다.
5. 검토 패키지와 공개 GitHub 스냅샷을 구별해야 한다. 현재 공개 커밋은 로컬에서 새로 수행한 모든 실험을 자동으로 포함하지 않는다. 개인정보·과거 대화·참가자 원문·제삼자 거울 복사·대용량 자료를 무심코 포함하지 않는다.

R1–R4와 통합 원형 물체의 “개발 실험 종료”는 실패 분석을 포함한 종료다. 이를 목표 능력 달성 또는 전체 후속 연구 완료라고 바꾸어 쓰지 않는다.
